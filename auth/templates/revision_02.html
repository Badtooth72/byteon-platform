2.1 ALGORITHMS

Think, design, trace and refine

Decomposition breaks a problem into smaller parts; abstraction keeps the details that matter and leaves irrelevant details out; algorithmic thinking builds a repeatable set of steps. Start a design by naming its inputs, processes and outputs. A structure diagram shows how a larger problem is divided into linked subproblems. Algorithms may be expressed in pseudocode, flowcharts or a high-level language.

Follow the state, not your intuition

A trace table records the value of variables after each important step or loop pass. In nested selection or iteration, note which branch runs and how many times the loop repeats. A syntax error prevents translation or running; a logic error lets a program run but produces the wrong result. A correction needs to address the reason for the error, not merely alter a final answer.

numbers = [3, 5, 2]
total = 0
for value in numbers:
    total = total + value
    print(total)
# Output: 3, 8, 10
Trace itThe running total is 3 after the first pass, 8 after the second and 10 after the third. If the line said total = value, the output would be 3, 5, 2: that is a logic error.

2.2 PROGRAMMING FUNDAMENTALS

Turn an algorithm into a program

A variable stores a value that can change; a constant is intended to remain fixed. Sequence runs statements in order, selection chooses a branch and iteration repeats statements. Count-controlled loops run a known number of times; condition-controlled loops run while a condition remains true. Be able to use arithmetic and Boolean operators, input and output, and assignment.

price = 7
quantity = 3
if quantity >= 3:
    total = price * quantity - 2
else:
    total = price * quantity
print(total)  # 19

Check operator precedence and data types. Integer, real, Boolean, character and string are common types. Input often starts as text: int(input(...)) casts suitable text to an integer. Choose a type that suits the value, such as Boolean for a yes/no state. Python's = assigns; == compares equality.

Organise data and code

  • Strings: concatenate text, select a character or slice part of a string.
  • Arrays/lists: store related values; a two-dimensional array can be thought of as rows and columns. A record groups different fields for one entity.
  • Subprograms: functions return a value, procedures perform a task. Parameters pass data in. Local variables belong to a subprogram; global variables have a wider scope.
  • Files: open, read or write, then close. SQL: use SELECT, FROM and WHERE to retrieve matching records. Random numbers: choose a value within a specified range when a program needs variation.

2.3 PRODUCING ROBUST PROGRAMS

Design for real users and test deliberately

Defensive design anticipates misuse and unexpected inputs. Input validation checks that supplied data is acceptable, such as whether a mark is an integer from 0 to 100. Authentication confirms a user's claimed identity; access permissions decide what the authenticated user may do. Clear names, indentation, comments and small subprograms make code easier to maintain.

Choose test data that can reveal a fault

Test typeExample for an age field accepting 11–16Expected action
Normal14Accept
Boundary11 and 16Accept both endpoints
Invalid17Reject: correct type, outside range
Erroneous"eleven"Reject: wrong data type for a number

Iterative testing happens while parts are developed; final testing checks the completed program. A test plan records the input, expected result, actual result and whether the test passed. When fixing a bug, repeat the failing test and check that existing behaviour still works.

mark = 50
if mark > 50:
    print("Pass")
# If 50 is a pass, the condition must be >= 50.
Spot the differenceThe program above runs, so its problem is a logic error. A missing colon after the if would be a syntax error.

2.4 BOOLEAN LOGIC

AND, OR and NOT

Boolean values are 1/0 or True/False. An AND gate outputs 1 only when both inputs are 1. An OR gate outputs 1 if at least one input is 1. NOT reverses a single input. Read a combined circuit one gate at a time and record intermediate outputs before calculating the final result.

ABA AND B (∧)A OR B (∨)
0000
0101
1001
1111

NOT 0 = 1 and NOT 1 = 0. The OCR core specification uses AND, OR and NOT. The symbols ∧, ∨ and ¬ are notation for the operators; circuit diagrams use recognisable gate shapes.

Work from the inside outFor ¬(A ∧ B) ∨ C with A=1, B=0 and C=0: A ∧ B = 0; ¬0 = 1; 1 ∨ 0 = 1.

2.5 LANGUAGES AND IDES

Tools for writing and translating code

High-level languages use constructs closer to human problem-solving and are generally easier to read and port. Low-level languages are closer to the processor's instructions and offer more direct hardware control. Computers ultimately execute machine code, so higher-level code must be translated.

A compiler translates a complete program before running the resulting executable; errors are typically reported after compilation. An interpreter translates and executes as the program runs, making individual statements easier to test but requiring interpretation each run. Real systems can combine approaches, so explain the model in the question rather than relying on a slogan.

Inside an IDE

An integrated development environment commonly includes an editor for writing code, error diagnostics to identify problems, a run-time environment for execution/testing and access to a translator. Explain how a named tool helps a developer: for instance, an error marker directs attention to a line that may break syntax.
